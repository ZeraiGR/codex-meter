# Codex Meter

Нативное приложение для строки меню macOS 14+. Показывает остаток квоты Codex, восстановление, статистику токенов и пользовательских задач. Работает с существующим входом в Codex через подписку ChatGPT. Для обновлений используется Sparkle. Отдельный API-ключ не требуется.

Карточка задачи показывает краткий итог; подробности открываются в «Деталях расхода».
В «Контексте выполнения» доступны параметры каждого запуска и записанные MCP-вызовы.
В переписке контекст открывается кнопкой ⓘ. [Источники данных и ограничения](execution-context.md).

## Запуск

```sh
bash scripts/build-app.sh
mkdir -p "$HOME/Applications"
ditto 'dist/Codex Meter.app' "$HOME/Applications/Codex Meter.app"
python3 scripts/install-integration.py
open "$HOME/Applications/Codex Meter.app"
```

Установка подключения сохраняет резервную копию `~/.codex/config.toml`, добавляет собственный `UserPromptSubmit` hook и скилл `codex-meter`. Подключение применяется к новым сессиям Codex. Настройки остальных интеграций сохраняются. Для удаления подключения удалите только блок `BEGIN CODEX METER` … `END CODEX METER` и каталог `~/.codex/skills/codex-meter`.

При первом запуске macOS запросит разрешение на уведомления. Автозапуск управляется в настройках приложения через системный ServiceManagement. Локальная сборка подписана ad hoc для этого Mac, не нотарифицирована для распространения.

## Использование

Установленная версия видна сразу в шапке панели рядом с названием Codex Meter.
Этот номер относится к запущенному приложению; доступная новая версия показывается
отдельно в уведомлении и строке обновления. Для самостоятельной установки нажмите
строку новой версии или «… → Проверить обновления…», затем подтвердите установку
в окне обновления. Круглая стрелка в шапке обновляет квоту, а не программу.

Светлая и тёмная тема следуют настройке macOS. Фон панели непрозрачный, цветные
значения и предупреждения имеют отдельные оттенки для обеих тем.

При назначении запроса, сохранении задачи или платежа, изменении статуса и объединении
задач появляется индикатор с названием операции. Кнопки, ввод и выбор в списках временно
заблокированы. Диалог закрывается только после сохранения и пересчёта статистики.
При ошибке изменения откатываются, форма остаётся открытой с введёнными значениями,
можно исправить данные и повторить действие. Повторные клики не создают новую операцию.

Фоновое обновление квоты и поиск сохраняют доступность интерфейса. У них свои индикаторы;
кнопка обновления квоты недоступна, пока выполняется предыдущий запрос.

- В настройках блок «Данные из Codex» показывает актуальность данных и время последнего обновления. По умолчанию путь искать и вводить не нужно. Ручной выбор исполняемого файла доступен в «Дополнительных настройках» и применяется отдельно от порогов уведомлений. Если вручную выбранный файл исчезнет, приложение попросит выбрать его заново или вернуться к автоматическому поиску.

- Текст и значения можно выделять и копировать через ⌘C. Кнопка рядом с ошибкой копирует сообщение вместе с техническими подробностями. При открытии настроек, статистики или платежей попап закрывается, а основное окно выходит вперёд.
- Временные ошибки подключения и внутренние ошибки сервера повторяются до двух раз с паузами 1 и 2 секунды. Для HTTP 403/429 быстрые повторы не выполняются. При неудаче сохраняются последние данные с исходным временем; автоматическая пауза растёт до 15 минут. Для 403 она начинается с 5 минут, для других сбоев — с 1 минуты. Успех возвращает обычный опрос раз в минуту; ручное обновление доступно сразу. HTML-страница ответа исключается из подробностей. Эти правила относятся к сборке с исправлением сетевых ошибок.
- Добавьте фактическую рублёвую оплату и оплаченный период на вкладке «Платежи». Новая оплата продолжает последний сохранённый период на один месяц; без истории предлагается месяц с сегодняшнего дня. Даты можно менять, сумму нужно ввести заново. После коротких месяцев сохраняется день оплаты. Конец периода — дата следующей оплаты; пересечения запрещены. Пустой платёж не заменяется выдуманной ценой.
- Для скилла агент отмечает конкретную пользовательскую задачу автоматически. Для другой работы скажите «начинаем задачу …», «продолжаем задачу …», «задача завершена». Скилл-помощник и агенты входят в исходную задачу. Пауза между ответами не означает её завершение.
- В разделе «Запуски» нажмите строку, чтобы прочитать запросы и ответы. Доступны вся переписка, поиск по полному тексту, фильтр служебных проверок и копирование. Полные сообщения читаются из исходных журналов по запросу; в базе остаются заголовки, фрагменты ответов и пути.
- В диалоге назначения и при объединении задач доступен список с поиском по названию и типу, фильтрами статуса и сортировкой по последней активности. Список прокручивается независимо от количества задач. Стрелки в поиске выбирают задачу, Enter в диалоге подтверждает назначение. Изменение поиска сбрасывает прежний выбор; обновление квоты его сохраняет.
- Старые запуски импортируются без выдуманных границ задач. На вкладке «Задачи» откройте «Запуски» и фильтр «Без задачи», назначьте их новой или существующей задаче. Названия и типы редактируются; задачи можно объединить.
- Рядом с остатком квоты показана доля прошедшего и оставшегося времени её периода. Обе шкалы показывают остаток; время считается от даты восстановления минус длительность окна и обновляется раз в минуту. Это период квоты, а не календарная неделя. После его окончания приложение ждёт новую дату восстановления.
- Пороги расхода по умолчанию: 50%, 80%, 90%, 95%. Дополнительно: за 2 дня и за сутки до восстановления недельной квоты, если осталось не менее 35%. При возвращении после сна приходит одно наиболее актуальное напоминание. Пороги настраиваются.

## Достоверность расчётов

Квоты читаются через документированный Codex App Server: `account/rateLimits/read`. Дневная статистика — `account/usage/read`. Журналы `sessions` и `archived_sessions` читаются локально; формат журналов не является стабильным API. Полная переписка не копируется, сохраняются короткие названия, идентификаторы, интервалы и счётчики.

Токены = вход + выход. Кэш — часть входа, reasoning — часть выхода; отдельно повторно не суммируются. Общая статистика сервера не складывается с локальной. Серверные дни могут поступать с задержкой, пропуски не считаются нулями.

Для стоимости используется основное самое длинное окно квоты Codex. Дополнительные ограничения моделей не добавляются как отдельные купленные ресурсы. Рубли = платёж × длительность окна / длительность оплаченного периода × израсходованная доля окна. Вся сумма платежа условно относится к Codex. Это стоимость ресурса, а не отдельное денежное списание или возврат.

В панели «Доступно сейчас» оценивает остаток текущего окна в пределах оплаченного периода; «Будущие восстановления» — ресурс будущих окон при неизменных условиях. Истёкшие окна не включаются в доступный остаток. Новый месяц не меняет прошлые платежи; исправление ошибочного платежа пересчитывает связанные оценки.

Доля квоты задачи вычисляется по последовательным снимкам не дальше 3 минут друг от друга в одном окне аккаунта. Требуется покрытие не менее 99% токенов задачи. При параллельной работе доля распределяется по токенам и помечается грубой оценкой; точного счёта по задачам сервер не предоставляет. Фоновая работа на других устройствах может влиять на наблюдение. Нет снимков, платёж неизвестен, округление счётчика, изменились условия или аккаунт — значение остаётся неизвестным, а не нулевым.

Прогноз использует завершённые задачи с явно подтверждённым типом из справочника (CLI также фильтрует модель); для уверенного сигнала нужны минимум 3 примера. Верхняя оценка — исторический 90-й процентиль с запасом 20%, не статистическая гарантия. Грубые параллельные оценки квоты в прогноз не включаются. Изменение модели, версии скилла, сложности или тарифа снижает применимость истории. Предупреждение не блокирует работу и не переключает модель.

Данные: `~/Library/Application Support/CodexMeter/meter.sqlite`. SQLite WAL позволяет приложению и CLI работать вместе. Для изолированной проверки можно задать `CODEX_METER_HOME`.

## CLI и проверка

```sh
'dist/Codex Meter.app/Contents/MacOS/codex-meter' --help
swift run --disable-sandbox meter-checks
python3 scripts/check-rpc.py 'dist/Codex Meter.app/Contents/MacOS/codex-meter'
'dist/Codex Meter.app/Contents/MacOS/codex-meter' ui-check
```

`check-rpc.py` проверяет транспорт на локальном подставном сервере в отдельной базе. Python нужен только для этой проверки. `ui-check` требует графической сессии macOS: проверяет закрытие панели, фокус нового/существующего/свёрнутого окна и копирование в отдельный тестовый буфер. В синтетической истории также проверяет высоту списка до выбора записи, ввод полнотекстового поиска, настоящий клик по строке, сохранение результатов при обновлении истории, минимальный размер окна и пустую выдачу.

В установленном здесь CLT 27 beta отсутствует SwiftUI macro plugin. Скрипт сборки использует установленный SDK 26.5. Для тестов в такой среде:

```sh
CLANG_MODULE_CACHE_PATH=/tmp/codex-meter-clang-cache \
SWIFTPM_MODULECACHE_OVERRIDE=/tmp/codex-meter-module-cache \
swift run --disable-sandbox --build-system native \
  --sdk /Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk meter-checks
```

Официальные источники: [App Server](https://learn.chatgpt.com/docs/app-server), [лимиты подписки](https://learn.chatgpt.com/docs/pricing), [hooks](https://learn.chatgpt.com/docs/hooks).

## Просмотр истории и оценки

Чтобы назначить несколько запусков, отметьте флажки прямо в списке «Запуски».
Клик по карточке открывает переписку и не меняет отметки. Нажатие флажка
меняет только один запуск; его область нажатия занимает 44 × 44 точки.
Просмотр стрелками и Esc также сохраняют группу. Esc закрывает просмотр.

В нижней панели видны число отмеченных запусков и действие «Назначить» для всей
группы. Если переписка не открыта, справа показан состав группы. Кнопка назначения
в заголовке открытой переписки относится только к этому запуску; после её сохранения
отметки остальных запусков сохраняются. Отмена любого диалога сохраняет группу.

Иконка флажка внизу выбирает или снимает выбор всей загруженной части выдачи.
Для следующих записей сначала нажмите «Показать ещё 100». Скрытые поиском или
фильтром записи исключаются из назначения и не возвращаются автоматически.
Крестик в нижней панели явно снимает все отметки.

Уже назначенные запуски можно перенести. При ошибке вся операция откатывается,
а диалог остаётся открытым для повторной попытки.
[Исследование взаимодействия и сценарии UX-проверки](multi-selection-ux.md).

Поиск по полному тексту запускается при изменении запроса или фильтров. Фоновое обновление истории не перезапускает его; кнопка обновления рядом со статусом поиска включает новые сообщения в результаты. Список и выбранная запись остаются доступными во время поиска.

Заголовок выбранного запроса отображается целиком и допускает выделение без изменения высоты. При назначении новая задача получает отдельное введённое название результата; текст запроса не подставляется. Тип по умолчанию — «Произвольная задача». Созданная из истории задача ожидает продолжения, её завершение отмечается отдельно. Проверки ui-check охватывают также выделение заголовка и сохранение назначения через диалог.

Карточка задачи суммирует стоимость всех запусков. Если снимков или оплаты не хватает, показывает учтённую стоимость и долю токенов с данными, не выдавая её за полный итог. В CLI tasks для этого доступны measuredRubles и costCoverage (0…1); rubles по-прежнему содержит только полный итог либо null.

При неполных данных приблизительный итог показывается отдельно: measuredRubles / costCoverage, без округления доли перед расчётом. Он уже включает учтённую часть, не заменяет rubles и не используется как измерение квоты для прогноза. CLI tasks возвращает его в projectedRubles; без положительной учтённой суммы и доли 0 < coverage < 1 результат null.


В основном списке задачи сортируются по недавней активности, токенам, времени выполнения,
учтённой стоимости, недельной квоте и названию. Направление переключается стрелкой;
неизвестные значения всегда в конце. Поиск по словам совмещается с фильтрами статуса
и конкретного типа из справочника, включая «Тип не указан». Сортировка сохраняет открытую карточку, фоновое обновление — условия списка.

Блок «Недельная квота» показывает измеренный процент независимо от платежей. При
неполном покрытии отдельно обозначены учтённая часть и полнота данных. Для нескольких
недель доли суммируются и могут превышать 100%; количество измеренных периодов указано
рядом. CLI `tasks` возвращает `weeklyQuota` с `points`, `coverage` и `windowCount` либо
null. Поле `quotaPoints` по-прежнему требует полного покрытия; прогноз не использует
частичную долю как итоговую.

## Когда терминальный Codex работает, а Meter получает 403

Приложение из меню macOS может не получить переменные прокси вашего терминала.
В дополнительных настройках «Данные из Codex» можно выбрать исполняемый скрипт,
который готовит такое же окружение и передаёт все аргументы настоящему Codex.
Скрипт не должен печатать служебный текст в stdout: этот поток используется протоколом.
Настройте постоянный способ запуска, а не порт прокси, живущий лишь до закрытия терминала.
HTTP 403 не лечится изменением процентов квоты. HTTP 429 требует паузы между запросами.

## Стоимость в долларах

Список задач и карточка показывают USD рядом с рублями. Формула: **USD = RUB / курс
рублей за 1 USD**. Для учтённой части и приблизительного итога перевод выполняется
отдельно, без округления исходных сумм. Например, при условном курсе 80 ₽ за доллар
учтённые 40 ₽ — ≈ $0.50, а итог 80 ₽ — ≈ $1.00. У всех задач, включая завершённые,
используется текущий курс; фактическая долларовая цена подписки из него не выводится.

Источник — [XML-сервис Банка России](https://www.cbr.ru/development/sxml/), запрос
на текущую дату в Москве. В карточке указаны дата действия и значение курса.
Обновление выполняется при запуске, затем раз в час; после ошибки повторяется через
15 минут независимо от доступа к квоте Codex. «Обновить курс» запускает запрос сразу.
Курс сохраняется локально. Ошибка обновления, сутки без успешного запроса или дата
курса старше семи суток отмечаются как сохранённый курс. В выходные доступен последний
действующий курс. Без сохранённого курса USD недоступен; отсутствие рублёвой оценки
также не заменяется нулём. CLI `tasks` сохраняет рублёвый контракт и не запрашивает курс.

## Предварительные даты и Telegram

При нулевом расходе сервер может сдвигать дату сброса вместе со временем запроса.
Meter помечает такой срок предварительным и скрывает шкалу прошедшего времени.
Смена недельного срока показывается с предыдущей датой и временем обнаружения.
Точный момент сброса между двумя опросами неизвестен.

[Настройка Telegram-бота](telegram.md) описывает лимиты, запросы к Codex, напоминания
и работу службы. Требуется отдельная привязка; разрешение macOS на уведомления
не влияет на Telegram.

## Несколько задач

В списке «Задачи» отмечайте карточки галочками. Открытие карточки и сортировка
сохраняют отметки. Кнопка слева внизу выбирает все задачи текущего поиска и фильтров;
крестик снимает отметки. Задачи, скрытые новым фильтром, исключаются из выбора.

Меню **«Действия»** относится к отмеченным задачам. **«Изменить статус»** переводит
их в работу, ожидание, завершённые, отменённые или неудавшиеся. История запусков
и расхода сохраняется. Повторное применение текущего статуса не меняет дату
завершения; возвращение в работу или ожидание снимает дату завершения.

**«Объединить задачи»** открывает выбор итоговой задачи. Можно выбрать одну из
отмеченных или другую существующую задачу. Все запуски и привязки переносятся в неё,
остальные выбранные карточки удаляются. Название, тип и статус итоговой задачи
сохраняются. Перед сохранением показаны получатель и число удаляемых карточек.
Автоматической отмены объединения нет; отмена диалога до сохранения не меняет данные.

Массовое действие сохраняется одной транзакцией. Если задача уже удалена или запись
не удалась, частичные изменения откатываются; окно показывает ошибку и позволяет
повторить действие. После успеха отметки обработанных задач снимаются.

## Справочник типов задач

Начиная с 1.4.11 тип выбирается из общего справочника в **Настройках → Типы задач**.
Начальный список включает разработку, исправление ошибки, ревью, исследование,
документацию и настройку/обслуживание. Названия можно менять и добавлять свои.
Пустые и повторяющиеся названия не сохраняются. Архивный тип остаётся у прежних задач
и в фильтрах, но не предлагается для новых назначений; его можно вернуть из архива.

Тип обозначает характер результата. Использованный скилл сам по себе не определяет
этот тип. Старые значения, включая имена скиллов, не подтверждаются автоматически:
такие задачи показывают «Тип не указан». В редакторе доступно прежнее значение для
справки. Чтобы классифицировать историю, выберите нужный тип в редакторе или отметьте
несколько задач и нажмите **Действия → Указать тип**.

Запуск наследует тип назначенной задачи. Пометка у запуска без типа открывает
редактор его задачи; если задачи ещё нет, сначала выберите или создайте её. Новую
задачу допустимо сохранить без типа, и пометка останется до явной классификации.
Переименование типа обновляет все связанные задачи. Фильтр использует устойчивый
идентификатор, поэтому не зависит от написания названия.

CLI `task-types` возвращает справочник. `task-start --type-id ID` и
`task-type --id TASK_ID --type-id TYPE_ID` используют существующий тип. `--skill`
сохраняет имя скилла отдельно. Старый `--kind` принимается для совместимости как
неподтверждённое значение и не создаёт тип. Повтор начала активной задачи с тем же
названием сохраняет её ID и классификацию независимо от скилла.

`forecast --type-id ID` выбирает только подтверждённые задачи этого типа. Без типа
прогноз остаётся неопределённым. Обновлённый hook задаёт это правило автоматически
после установки новой версии приложения; для обновления отдельно установленной
копии скилла повторите установку интеграции из актуальных исходников.

# Выбор нескольких запусков

## Задача и исследование

Пользователь просил убрать предварительную кнопку «Выбрать несколько» и сделать
массовое назначение естественной частью списка. Исследование выполнено 25 октября
2026 по официальным руководствам продуктов. Популярность продукта сама по себе
не доказывает удобство конкретного решения; ниже сравниваются применимые механики.

| Продукт | Наблюдаемый подход | Применение в Meter |
| --- | --- | --- |
| [Linear](https://linear.app/docs/select-issues) | Флажок у строки, выбор клавиатурой, Esc, действия для выбранной группы. | Начинать выбор прямо в списке, показывать действия по контексту. |
| [Notion](https://www.notion.com/en-gb/help/tables) | Флажки у строк и выбор всех; меню массового изменения появляется после выбора. | Флажок позволяет выбрать несколько строк без знания клавиш. |
| [Superhuman](https://new.superhuman.com/multiselect-29111) | ⌘-клик и ⇧-клик, расширение выделения клавиатурой. | Сохранить быстрый привычный способ выбора без режима. |
| [Figma, список слоёв](https://help.figma.com/hc/en-us/articles/360040449873-Select-layers-and-objects) | ⌘ добавляет отдельные строки, ⇧ выбирает диапазон. | Использовать поведение списка, а не жесты рисования рамки на холсте. |
| [macOS](https://support.apple.com/en-sg/guide/mac-help/mchlp1378/27/mac/27) | Обычный клик, ⌘-клик, ⇧-клик и ⌘A. | Оставить системную модель выделения, поддерживаемую нативным списком. |

## Решение

В Meter флажки видны у запусков постоянно. Это небольшое отличие от появления
только при наведении в Linear и Notion: способ выбора обнаруживается без знания
скрытого жеста. Флажок и нативная подсветка показывают одно состояние.
Обычный клик выбирает один запуск и открывает переписку; ⌘-клик добавляет или снимает
отдельный запуск, ⇧-клик выделяет диапазон. Стрелки с ⇧ расширяют выбор.

Постоянная нижняя строка содержит выбор показанных записей и число результатов.
При выделении в ней появляются счётчик, действие «Назначить» с иконкой и крестик
сброса. Высота списка сохраняется. Иконки имеют доступные названия и подсказки;
главное действие оставлено с коротким текстом, чтобы не требовать угадывания иконки.
Esc снимает выделение в списке. В поле поиска «Выделить всё» относится к тексту.

При выборе группы справа показаны число и названия выбранных запусков, а также
действие назначения. Это исключает ситуацию, когда массовая операция выглядит
как действие над единственной открытой перепиской. Диалог назначения остаётся общим
для существующей и новой задачи; запись выполняется прежней атомарной операцией.

Выбор всех ограничен загруженными строками текущей выдачи. Следующие страницы
не включаются молча. Поиск и фильтры исключают скрытые записи из выделения;
возврат прежнего фильтра не восстанавливает их автоматически. Фоновое обновление
сохраняет выделение по идентификаторам оставшихся показанных запусков.

## Проверка UX

Используются экспертный проход по сценариям, автоматизированные действия мышью
и клавиатурой в настоящем macOS-интерфейсе и визуальный осмотр. Это не исследование
с внешними участниками: скорость людей, удовлетворённость и процент успешности
пользователей не измерялись.

Критерии приёмки: выбор без режима; согласованность флажков и строк; диапазон и
разрозненный набор; сброс; неизменная высота списка; ясное групповое состояние;
сохранение выбора при обновлении; исключение скрытых и незагруженных записей;
доступность одиночного просмотра и прежнего назначения без потери данных.

Для двух отдельных строк путь до диалога сокращён с четырёх кликов
(режим, два флажка, назначение) до трёх (два флажка, назначение).
Это подсчёт действий интерфейса, а не измерение времени пользователя.

Нативный сценарий подтверждает флажки, ⌘-клик, ⇧-клик, ⇧↓, Esc, назначение
ровно двух выбранных строк и сохранение группы после отмены. При 105 результатах
действие выбора показанных передаёт в диалог только 100 загруженных запусков.
Проверены исключение скрытых строк, сохранение выбора при обновлении и выделение
текста поиска независимо от списка. Светлая и тёмная темы просмотрены на
синтетических данных, включая минимальное окно 840 × 620 и окно 980 × 740.
Полный проход VoiceOver и тестирование с внешними участниками не проводились.

# Контекст запуска и задачи

Карточка задачи показывает краткие итоги: токены, активное время, учтённую стоимость
и недельную квоту. «Детали расхода» раскрывают вход, кэш, выход, reasoning-токены,
полное время, покрытие измерений и расчёт стоимости. Прогноза следующей похожей
задачи в карточке нет; команда CLI `forecast` остаётся доступной для учёта задач.

В разделе «Контекст выполнения» видны сочетания модели и уровня рассуждения.
Раскрытие показывает каждый входящий запуск с его параметрами и инструментами.
В просмотре переписки тот же контекст открывается кнопкой ⓘ рядом с переключателем
«Этот запуск / Вся переписка».

## Что записано

Импортёр читает факты из локального JSONL, а не подставляет сегодняшние настройки
в прошлые запуски. Идентификатор модели и effort берутся из `turn_context`.
Если параметры менялись внутри запуска, сохраняются отдельные последовательные
сочетания с приращениями токенов, полученными при каждом из них. `service_tier`
и провайдер сохраняются из записанных настроек диалога; размер контекста берётся
из события начала запуска. Отсутствующий контекст следующего запуска не наследует
модель предыдущего.

Harness представлен клиентом, его версией и источником из `session_meta`:
`originator`, `cli_version`, `source`. Это сведения при создании диалога.
Если его возобновили другим клиентом или после обновления Codex, исходная запись
не подтверждает версию клиента нового запуска.

Фактические MCP-вызовы читаются из `event_msg.item_completed` с типом `McpToolCall`.
Сохраняются сервер, имя инструмента, ID события, статус, время завершения и длительность,
если она присутствует. `result.isError` учитывается как ошибка даже при статусе
завершённого транспортного вызова. Повтор одного ID не увеличивает число вызовов.
Из того же потока доступны события команд, изменения файлов и просмотра изображений.
Аргументы, ответы инструментов, системные инструкции и внутренние рассуждения
в эти метаданные не копируются.

## Границы полноты

Полный исторический список доступных MCP в поддерживаемых журналах не сохранён.
Использованный инструмент подтверждает конкретный вызов, но не описывает весь
набор доступных инструментов. Настройки MCP допускают отключение серверов,
allow/deny-списки и подключение через плагины, поэтому чтение текущего `config.toml`
не восстановит прошлую доступность. [Официальная документация MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

Имя модели показывается без сокращения, включая версию, если она есть в самом
идентификаторе. Псевдоним не превращается в выдуманную точную серверную ревизию.
Уровень рассуждения является настройкой модели, а reasoning-токены являются
частью фактического расхода. Это разные величины.
[Справочник настроек Codex](https://learn.chatgpt.com/docs/config-file/config-reference)
описывает model, reasoning effort, provider и context window.

Пустой список событий означает отсутствие записанной телеметрии, а не доказанное
отсутствие инструментов. Старые форматы без `item_completed` не обеспечивают эту
детализацию. Поддержка произвольных внешних harness не заявляется.

Контекст помогает сравнивать условия работы, но не превращает число токенов в
универсальную оценку качества или цены. Разные модели, объём кэша и уровень
рассуждения могут давать разную стоимость и результат при одинаковом числе токенов.

## Хранение и обновление

`RunRecord.execution` является необязательным полем JSON в существующей SQLite-базе.
Старые записи продолжают читаться. Версия отпечатка импорта `execution-v1` заставляет
однократно перечитать доступные журналы, сохраняя назначения задач, платежи и счётчики.
Если исходный файл удалён, восстановить отсутствовавшие метаданные нельзя; прежняя
запись остаётся доступной. Повторный импорт неизменённого файла не дублирует данные.

Проверки используют синтетические журналы: смена настроек, неизвестная модель,
дедупликация MCP, ошибочный ответ, сохранение в SQLite и повторный импорт старых
записей с привязками. UI-сценарии проверяют свёрнутую детализацию и контекст запуска;
снимки покрывают обе темы и минимальное окно.

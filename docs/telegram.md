# Telegram: лимиты, напоминания и запросы к Codex

Telegram работает отдельной фоновой службой на Mac. Каждый пользователь подключает
своего бота и подтверждает личный аккаунт. Стандартный модуль отвечает о квоте
и отправляет выбранные уведомления. Запросы Codex являются отдельной расширенной
интеграцией и не включаются через обычную настройку уведомлений. В установочном пакете нет токена,
получателя, сохранённых диалогов или настроек владельца проекта. Основное приложение
работает и без Telegram. Нужны Python 3.10+, установленный Codex с подписочным входом
и доступ к Telegram Bot API.

## Подключение из приложения

В версии 1.4.19 откройте **Настройки → Telegram**. Создайте отдельного бота через
`/newbot` у [BotFather](https://t.me/BotFather), затем введите токен в скрытое поле.
Не отправляйте токен в переписку. Если Python не найден, установите его с
[python.org](https://www.python.org/downloads/macos/) и выберите исполняемый файл
в дополнительных настройках. Сам Meter не устанавливает Python.

Выберите разрешения и нажмите **Подключить бота**. Приложение проверит токен и
покажет одноразовую ссылку. Откройте её своим Telegram-аккаунтом, нажмите Start,
вернитесь в Meter и нажмите **Я нажал Start — проверить**. Ссылка действует десять
минут. Не пересылайте её: она определяет владельца. Проверка токена сама по себе
не создаёт привязку. Отмена или истечение ссылки сохраняют прежнее подключение.
Бот с действующим webhook не подключается, чтобы не нарушить чужую интеграцию.

После подтверждения видны имя бота, ID владельца и состояние модуля. Служба
запускается при входе в macOS и работает независимо от окна Meter. **Выключить**
останавливает её и отключает автозапуск, сохраняя привязку. **Включить** запускает
снова. **Отключить привязку** удаляет активный токен и владельца; приватная копия
прежних настроек и диалогов остаётся в `previous`, без копии токена. Перед остановкой
интерфейс предупреждает, что запросы прервутся, а уже изменённые файлы не откатятся.

## Разрешения

Каждую категорию можно включить независимо:

- Ответы о квоте по `/limits`. При отключении команда не запрашивает измерение;
  `/status` также не показывает квоту.
- Напоминания перед восстановлением. Часы задаются через запятую, по умолчанию 48, 24 и 6.
- Сообщения об изменении окна квоты.

Запросы Codex не входят в стандартное подключение. Они настраиваются отдельно
через установщик из исходников с `--allow-codex`, рабочей папкой и режимом sandbox.
Если такой бот был подключён раньше, настройки уведомлений сохраняют его прежние
разрешения и диалоги. Обычный пользователь не включает выполнение кода случайным
переключателем в настройках уведомлений.

Служебные ответы на команды остаются доступны, пока модуль включён. Для полного
прекращения обмена выключите модуль. Платежи и история задач Meter автоматически
не пересылаются. Системные уведомления macOS и Telegram имеют отдельные настройки.

Отключённые категории не отправляются даже из очереди. Старые сообщения без категории
не отправляются, если хотя бы одно разрешение ограничено. Ранее настроенные боты
сохраняют прежние разрешения до явного изменения в приложении.

**Сохранить настройки Telegram** перезапускает включённую службу, обновляя её код
из приложения. Диалоги и привязка сохраняются. Если выполняются запросы, сохранение
попросит дождаться их окончания или сначала выключить модуль. Изменить рабочую папку
после появления диалогов Codex можно через отключение и новую привязку, чтобы история
одного проекта не продолжалась в другом. При подключении другого бота прежние ответы
и диалоги не переносятся новому получателю. Обновление самого Meter не запускает
и не перенастраивает существующую службу без действия пользователя.

## Подключение через терминал

Для ручной установки из исходников сохранён отдельный установщик:

```sh
python3 integrations/telegram/setup.py \
  --workspace "$PWD" \
  --codex /path/to/codex \
  --meter "/Applications/Codex Meter.app/Contents/MacOS/codex-meter" \
  --sandbox read-only
```

Укажите существующий исполняемый Codex или сетевой launcher. Для запросов Codex
добавьте `--allow-codex`; без него доступны только квота и уведомления. Токен вводится
скрыто, затем установщик ждёт Start по одноразовой ссылке. Повторная ручная настройка
меняет привязку и начинает новый диалог. Для сохранения истории при изменении
разрешений уведомлений используйте настройки приложения. Расширенные запросы Codex
могут читать данные проекта и доступных инструментов, а в режиме `workspace-write`
изменять файлы. Такое подключение требует отдельного осознанного выбора.

## Доступ через VPS при включённом VPN

Если прямое соединение с Bot API недоступно, Telegram-служба может использовать
локальный TCP-туннель через VPS. Codex продолжает работать через свой сетевой
launcher. Telegram-приложение и системный VPN сохраняют свои настройки.

На Mac нужен SSH-доступ к VPS по ключу. Для ручного запуска туннеля используйте
свой SSH alias вместо `my-vps`:

```sh
ssh -NT -o BatchMode=yes -o ExitOnForwardFailure=yes \
  -o ServerAliveInterval=30 -o ServerAliveCountMax=3 \
  -L 127.0.0.1:18443:api.telegram.org:443 my-vps
```

В дополнительных настройках Telegram укажите локальный порт `18443`.
Приложение сохраняет `network.json` в приватной папке Telegram с правами 0600.
При ручной настройке содержимое файла: `{"tunnel_port":18443}`. Его читают
установщик и фоновый бот при запуске. Порт должен совпадать с локальным
портом туннеля. SSH передаёт TCP, а бот устанавливает HTTPS до `api.telegram.org`
с проверкой сертификата и имени сервера. Токен не передаётся VPS в открытом виде.
Слушающий порт привязан только к loopback.

Для постоянной работы на настроенном Mac туннель запускает отдельный LaunchAgent
`local.codex-meter.telegram-tunnel`. Он восстанавливает SSH после разрыва связи
и запускается при входе в macOS. Его plist находится в `~/Library/LaunchAgents/`,
а журнал `tunnel.log` в приватной папке Telegram. Проверить и перезапустить его:

```sh
launchctl print "gui/$(id -u)/local.codex-meter.telegram-tunnel"
launchctl kickstart -k "gui/$(id -u)/local.codex-meter.telegram-tunnel"
```

При недоступном туннеле бот сообщает сетевую ошибку, сохраняя ответы в очереди.
Автоматического перехода на прямое соединение нет. Для возврата к обычному доступу
очистите поле порта и сохраните настройки. Сам туннель можно остановить
через `launchctl bootout`, а его plist удалить для отключения автозапуска.

## Команды и выполнение

| Команда | Результат |
| --- | --- |
| `/limits` | Запрос свежей квоты без обращения к модели; при ошибке показывает последнее измерение. |
| `/status` | Состояние выбранной сессии, число активных запросов и последнее измерение квоты. |
| `/new [название]` | Создаёт и выбирает сессию. Запросы в других сессиях продолжаются. |
| `/sessions` | Показывает сохранённые сессии и кнопки выбора, по восемь на странице. |
| `/use ID` | Выбирает сессию по номеру из списка. |
| `/cancel` | Останавливает запрос выбранной сессии. Уже сделанные изменения файлов не откатываются. |
| `/help` | Команды, рабочая папка и режим доступа. |

Обычный текст продолжает выбранную сессию Codex. Например, отправьте `/new Обзор`,
задайте вопрос, затем отправьте `/new Документация` и второй вопрос. Оба запроса
выполняются параллельно. Вернуться к первому диалогу можно кнопкой в `/sessions`
или командой `/use ID`. Выбор действует на следующие сообщения и `/cancel`.
Ответы приходят с номером и названием исходной сессии, даже если вы уже переключились.

По умолчанию одновременно выполняются три запроса, по одному на сессию.
Параметр `max_parallel` в приватном `config.json` допускает целые числа от 1 до 8
и применяется после перезапуска службы. Когда все места заняты, бот отклоняет
новый запрос и просит отправить его позже. Очереди отложенных запусков нет.
Обновление квоты имеет отдельное место и доступно при занятых сессиях.

У каждой сессии своя история диалога. Все сессии используют одну рабочую папку,
выбранную при установке. Автоматических Git worktree нет. Одновременные изменения одного
файла могут конфликтовать, поэтому такие задачи выполняйте последовательно.
Список содержит диалоги этого бота. Чаты приложения Codex автоматически не импортируются.
Команды и кнопки используют обычный [Telegram Bot API](https://core.telegram.org/bots/api).

На один запрос отведено 30 минут. Сообщения старше десяти минут не запускаются
автоматически после долгого отключения Mac. После перезапуска прерванная задача также не повторяется:
бот просит прислать её заново. Изображения, голос и вложения пока не поддерживаются.

Codex использует текущие локальные модель и настройки. В режиме `workspace-write`
разрешены изменения проекта в рамках sandbox. Запросы на расширение полномочий
автоматически отклоняются (`approval_policy="never"`); бот не включает полный доступ.
Доступные MCP-интеграции и правила проекта остаются частью локальной конфигурации
Codex. Telegram-команды не являются отдельной оболочкой для произвольных shell-команд.

## Когда приходят напоминания

Бот опрашивает квоту примерно раз в минуту. После ошибки делает паузу пять минут.
За 48, 24 и 6 часов до указанного сервером недельного сброса он отправляет остаток,
если он больше нуля. После сна отправляет только ближайшее актуальное напоминание.
Состояние сохраняется на диске, поэтому перезапуск и колебание срока в пределах
90 секунд не повторяют уведомление. Изменение окна вызывает отдельное сообщение, если эта категория разрешена.

Данные старше трёх минут не используются для напоминаний. При нулевом расходе
сервер иногда возвращает текущий момент плюс полную длительность окна, сдвигая
дату при каждом запросе. Такой срок помечается предварительным и не запускает
напоминания. Бот не назначает сброс на определённый день недели и не считает
истёкший срок доказательством восстановления. Время показывается с часовым поясом Mac.

**Mac должен быть включён, не спать и иметь доступ к сети.** Во время сна бот
не отправляет сообщения и не выполняет запросы. После пробуждения он перечитывает
квоту. Внезапный серверный сброс раньше объявленного срока предсказать невозможно.
Если Telegram недоступен, ответы остаются в локальной очереди. При потере ответа
Telegram после фактической доставки возможно повторное сообщение; модель при этом
не запускается повторно.

## Данные и обслуживание

В `~/Library/Application Support/CodexMeter/telegram/` находятся `config.json`,
`token`, `state.json`, копия `bot.py` и `service.log`. Каталог имеет права 0700,
токен, настройки и состояние 0600. Состояние содержит список сессий с названиями
и ID диалогов Codex, выбранную сессию, последнее измерение, отметки напоминаний
и неотправленные ответы. При обновлении прежний единственный диалог переносится
в сессию «Основной», очередь ответов и отметки напоминаний сохраняются.
При перезапуске бот сообщает о каждом прерванном запросе и не запускает его повторно.
Полные журналы диалога хранит обычный Codex. Бот не отправляет в Telegram платежи и историю Meter,
но ответы Codex могут содержать информацию из выбранного проекта.

В приложении обновление кода службы выполняется при сохранении настроек Telegram
или включении ранее выключенного модуля. Для установки из исходников можно обновить
приватную копию вручную и перезапустить службу:

```sh
cp integrations/telegram/bot.py "$HOME/Library/Application Support/CodexMeter/telegram/bot.py"
launchctl kickstart -k "gui/$(id -u)/local.codex-meter.telegram"
```

Проверка и остановка:

```sh
launchctl print "gui/$(id -u)/local.codex-meter.telegram"
launchctl bootout "gui/$(id -u)/local.codex-meter.telegram"
```

Для отключения автозапуска после остановки удалите только
`~/Library/LaunchAgents/local.codex-meter.telegram.plist`. Приватную папку сохраняйте
для восстановления либо удалите после отзыва токена в BotFather. Основная база Meter
от этой операции не меняется. Не запускайте две копии с одним токеном; webhook для
этого бота должен быть отключён. Файловая блокировка защищает от второго локального
процесса с тем же каталогом состояния.

Исходники и изолированные проверки находятся в `integrations/telegram/` и
`Tests/telegram/`. Подключённым бот считается только после привязки, доставки
сообщения и успешного `/limits`; наличие исходников само по себе этого не доказывает.
